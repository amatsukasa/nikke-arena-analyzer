# 固定ページの編集方法

このフォルダにあるMarkdown（マークダウン）ファイルを書き換えると、サイトの固定ページを更新できます。プログラムのファイルを編集する必要はありません。

## まず、どのファイルを編集するか

サイトのメニュー名と、編集するファイルの対応は次のとおりです。

| メニュー | 編集するファイル |
| --- | --- |
| ABOUT | `frontend/content/about.md` |
| GUIDE | `frontend/content/guide.md` |
| LINK | `frontend/content/links.md` |
| UPDATE | `frontend/content/updates.md` |

文章だけを変更する場合は、上記4ファイル以外のプログラムを触る必要はありません。TOPは分析画面そのものなので、Markdown編集の対象外です。

## ファイルの役割

- `about.md`：サイトの説明、運営者、著作権、免責事項
- `guide.md`：サイトの使い方、分析結果の見方、注意点
- `links.md`：公式サイトやおすすめサイトのリンク集
- `updates.md`：機能追加、不具合修正、再集計などの更新履歴

ファイル名を変更するとページが表示できなくなるため、名前はそのままにしてください。

## ページ上部の情報（Front Matter）

各ファイルの先頭には、ページ名などを書く場所があります。

```md
---
title: ページの名前
description: ページの短い説明
updatedAt: 2026-07-26
---
```

- `title`：ページ上部に大きく表示される名前です。
- `description`：ページ名の下に表示される説明です。
- `updatedAt`：更新日です。`年-月-日`の順で記載します。

更新日を表示しない場合は、`updatedAt`の行を削除しても問題ありません。先頭と末尾の`---`は削除しないでください。

## 見出しの書き方

ページの一番大きな見出しは、Front Matterの`title`から自動で表示されます。本文には`#`が1つの見出しを書かず、`##`から使用してください。これにより、ページ内の大見出しが重複するのを防げます。

```md
## 本文の大きな見出し
### 本文の小さな見出し
```

誤って本文に`# 見出し`と書いた場合も、サイトでは`##`相当の見出しとして表示されます。

## 箇条書きの書き方

```md
- 項目1
- 項目2
- 項目3
```

番号を付ける場合は次のように書きます。

```md
1. 最初の項目
2. 次の項目
3. 最後の項目
```

## リンクの書き方

```md
[サイトに表示する名前](https://example.com/)
```

URLは、リンク先のページをブラウザで開いて確認してから記載してください。例にある`example.com`は説明用のURLです。

## 画像の書き方

画像は`frontend/public/content-images/`へ置くことをおすすめします。フォルダがない場合は作成してください。

例えば`frontend/public/content-images/guide.png`を置いた場合は、次のように書きます。

```md
![画像の内容を説明する文章](/content-images/guide.png)
```

`[]`の中には、画像が見えない場合にも内容が伝わる短い説明を書いてください。

## そのほかの書き方

```md
**太字にする文章**

> 引用や特に注意してほしい文章

文中の`短いコードや項目名`

---
```

複数行のコードは、コードの前後を3つのバッククォートで囲みます。

## 安全上の注意

Markdown内にHTMLタグを書いても、HTMLとしては実行されません。`<script>`などの生HTMLや、任意のReactコンポーネントは使用できません。安全のため、本文はこのREADMEで説明しているMarkdownの書き方だけを使用してください。

`javascript:`から始まる危険なリンクや画像URLは表示されません。外部サイトへのリンクは新しいタブで開き、安全用の属性が自動的に設定されます。

## 編集内容をサイトへ反映するには

Markdownファイルを保存しただけでは、公開中のサイトは自動更新されません。変更内容をGitへ反映し、サイトを再デプロイしてください。手順が分からない場合は、普段サイトを更新している担当者へ依頼してください。
