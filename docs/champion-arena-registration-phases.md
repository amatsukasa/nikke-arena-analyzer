# 正式版チャンピオンアリーナ：段階別編成登録

## 適用範囲と既存データ

大会形式 `registration_scope`（full_64 / champion_8）と、新設した `deck_registration_phases`（段階別登録の有効化）は別の設定。
既存の `is_champion_arena` は戦績入力対象の指定であり、正式版の判定には使用しない。
新フラグの既定値は false。既存大会・β版・通常の64人モードは有効化しなければ従来の画面・保存規則を維持する。

既存シーズン1では、大会管理の編集画面で「正式版の段階別編成登録を有効にする」をオンにする。
既存の大会ID・選手ID・シード・枠・DeckSet・Match・RoundResultを書き換える必要はない。
公開中は編集を禁止する既存方針を継続するため、編成・結果の追加時にはいったん非公開にする。
ベスト16までの既存結果から進出者を計算し、ベスト8進出者だけが空欄から再登録できる。
新しい履歴が存在した後はフラグを無効化できない。履歴のある大会の既存削除APIも409で停止する。

## 登録段階

| 大会形式 | 段階 | 適用試合 |
| --- | --- | --- |
| full_64 | initial | Best 64、32、16 |
| full_64 | best8 | Best 8、4 |
| full_64 | final | 決勝 |
| champion_8 | initial | Best 8、4 |
| champion_8 | final | 決勝 |

champion_8 に best8 登録段階は存在しない。入力UI、5編成の構造、既存の画像解析・アイコン切り抜きコンポーネントは共有する。
新段階へ編成をコピーしない。5編成・25枠が解決済みになって初めて保存・完了となる。
未登録は未完了として表示し、不正ID・重複キャラクター・部隊番号不整合は422で拒否する。空き枠9999は従来同様許可する。

## 追加型データモデル

- tournaments.deck_registration_phases: Boolean、既定false。
- arena_deck_registrations: 選手・段階・進出資格トークン・5編成JSON・作成日時。更新時も新規行を追加。
- arena_match_revisions: 試合枠・段階・上流トークン・両選手・勝者・5ラウンド結果・両編成の登録版IDと編成スナップショット。結果訂正も新規行を追加。
- 既存DeckSet/DeckTeamは初回登録として読む。既存Match/RoundResultは旧初回編成を参照し続ける。
- 一括変換、既存行の削除・再採番、uploadsの移動は行わない。
- Alembic revision `c0f6e4a8b123`、親 `b9e5d3f7a012`。スキーマのupgradeが必要。今回DBへの実行は行っていない。
- downgradeは履歴消失を防ぐため自動実行を拒否する。復旧時には追加テーブルと設定を保持したままコードの切り戻しを検討し、履歴を含むバックアップと個別計画を用意する。

旧結果には当時の版番号がない。そのため、有効化後は旧保存・結果訂正APIを409で止め、旧DeckSet/Matchを変更しない方式で参照を固定する。
新APIでは明示的な版IDとスナップショットを保存する。機能導入以前にすでに上書きされた編成を復元する機能ではない。
full_64の旧結果は従来のブラケットと同じく対戦者の組合せで特定する（自由入力のstage文字列には依存しない）。champion_8は既存のstage/slotを使う。

## 進出判定・同時更新

試合枠を大会形式から構築し、上流の有効な勝者だけで後続の参加者を決める。
ベスト8はBest16の勝者、決勝は準決勝の勝者にのみ資格を付与する。
登録と結果保存は同一Tournament行をロックし、その後に資格を再評価する。
古い画面からの保存は、資格・登録版・結果版・上流トークンの不一致で409となる。

上流の結果を訂正した場合、下流の既存行は削除せず現行ブラケットから除外する。
変更後の資格トークンに一致する編成だけを使用し、新しい資格では空欄・未登録として再評価する。
保守的な規則として、同じ勝者であっても上流結果を新しい版として保存すると下流の資格を更新する。必要な再登録・結果再確認を行う。
資格を失った選手の編成、現在のブラケットから外れた結果、旧初回編成は「保存履歴」で参照できる。

保存応答には最新の登録状況・ブラケット・統計を含める。フロントエンドは応答を反映するため、登録後の手動更新や新設ポーリングは不要。

## API

- GET `/api/tournaments/{id}/arena-phases`: 段階・有資格者・登録編成・試合枠・段階別統計。
- GET `/api/tournaments/{id}/arena-phases/history`: 旧データを含む読み取り専用履歴。
- POST `/api/tournaments/{id}/arena-phases/players`: 新しい選手を空きシード／枠へ追加。既存選手の置換は拒否。
- PUT `/api/tournaments/{id}/arena-phases/players/{player_id}/{initial|best8|final}`: 資格・現在の版を検証して新規版を追加。
- PUT `/api/tournaments/{id}/arena-phases/matches/{remaining}:{slot}`: 両選手の該当段階の完成編成と上流状態を確認し、5ラウンド結果を追加。

閲覧は既存の大会閲覧権限、更新は管理者／大会作成者かつ非公開大会に限定する。
Next.jsプロキシは上記パス・メソッドのみ転送する。APIのJSONには画像本体を保存しない。
既存の画像解析とプレイヤーアイコンアップロードAPIを再利用する。段階別保存は編成情報だけを保存し、テンプレート学習は行わない。

## 統計・画面

登録画面とダッシュボードは同じ段階別ビューを使う。閲覧者には編集機能を出さない。
日本語・英語・フランス語・韓国語・中国語に新規文言を追加。
段階別の採用率は現在の有資格者の登録編成を分母にし、勝率は試合結果に固定した編成から計算する。
旧結果は初回登録として集計し、新しいベスト8・決勝結果と混在させない。

既存の詳細分析・大会横断の統計APIは初回登録を対象とする。APIにはregistration_phase=initialを付記する。
初回の新しい登録版も集計に含め、勝率には結果のスナップショットを使用する。
段階別大会では旧スナップショットを集計元にせず再計算する（古い混合集計の使用を回避）。
既存の「Top 8 Compositions」はベスト8進出者の初回登録編成である。新しいベスト8登録編成は段階別ビューに表示する。
既存詳細分析へはダッシュボードの「初回登録の詳細分析」から移動できる。
